# Agent Pigeon v0.1 Release Candidate

- Date: 2026-09-22
- Branch: `poc/v0.1-rc` (based on `poc/04c-autonomous-evidence` `5d4c286`; HEAD also contains the merged PR #2 from origin)
- Final regression: **77/77 tests pass** (71 prior + 6 new CLI/install integration tests)

## Product shape chosen

**v0.1 = two commands, one policy.**

```
agent-pigeon replay   # zero-setup: mine local Claude/Codex history for verification debt (read-only)
agent-pigeon init     # optional: install the live VERIFY_FIRST governor (Claude Code hooks)
agent-pigeon remove   # clean uninstall of exactly what init added
```

That is the entire product surface. VERIFY_FIRST is the only intervention. RETHINK,
HUMAN_REVIEW and Jev are not part of v0.1.

## Why this shape

- **Replay-first** (POC-04B/04C evidence): the only validated organic findings — 28
  verification-debt windows, 2 productive loops — came from history replay, which needs
  zero configuration and zero risk. A stranger gets their first answer ("does my agent
  collect proof?") in under a minute without touching any hook.
- **Live governor second** (POC-04A/04A.1 evidence): proven end-to-end locally, but its
  effect on real Claude behavior is unmeasured (quota) — so it ships as an explicit,
  inspectable, removable opt-in, not the default experience.
- **General core, mobile flagship adapter** (POC-04C direction B): verification
  classification already covers gradle/adb/logcat/agent-device; the deep runtime adapter
  (POC-01) stays research/experimental until Android tooling is commonly present.

## User journey (actual commands, verified)

```bash
git clone https://github.com/hyukvoid/agent-pigeon && cd agent-pigeon
npm install && npm run build

npx agent-pigeon replay                       # first value, read-only
npx agent-pigeon init --dry-run               # inspect exactly what will be installed
npx agent-pigeon init                         # adds 2 hooks to ./.claude/settings.json
npx agent-pigeon remove                       # removes them again, preserves your other hooks
```

Verified in a clean directory against the packed tarball (see Package).

## What was removed (and why)

- `deliver-verify-first.mjs` / UserPromptSubmit delivery — superseded by the PostToolBatch
  in-process delivery (POC-04A.1); the batch hook computes its own decision, so no racing
  worker is shipped.
- POC scenario CLIs moved out of the product surface: `poc:00` demo → `npm run demo`
  (bundled fixtures only), research runners stay as dev scripts
  (`research:corpus`, `poc:01/03/035`, `governor:process`) and are excluded from the
  npm package.
- Jev provider removed from the MVP path (interface retained in source; no command exposes it).
- RETHINK/HUMAN_REVIEW: not computable, not deliverable, not present in the product layer.

## Live governor experience (actual behavior)

`init` prints what gets installed, then merges into `.claude/settings.json`:

```json
"PostToolUse":  [{ "matcher": "Edit|Write|MultiEdit|Bash",
                   "hooks": [{ "type": "command", "command": "node \"…/hooks/hook-posttooluse.mjs\"", "async": true }] }],
"PostToolBatch": [{ "hooks": [{ "type": "command", "command": "node \"…/dist/src/governor-batch.js\"", "timeout": 30 }] }]
```

Verified: idempotent re-init ("already installed"), unrelated existing hooks preserved,
clean remove, corrupt/unparsable settings file → init aborts without touching the file.
Warning text is fixed and factual ("…N materially different implementation changes were
made without collecting new verification evidence. / Verify the current app before
another implementation change."), once per debt episode.

**Live behavioral effect on Claude: still UNVALIDATED (account access).** v0.1 claims
detection and delivery, not behavior change.

## Mobile support

Ships: verification classification for gradle/gradlew, adb, logcat, emulator,
agent-device commands (replay flags mobile sessions; live governor counts device runs as
verification evidence). Research/experimental (not in product surface): agent-device
runtime adapter, crash/screen signatures, REAL A/B/C emulator experiments.

## Privacy

- **Reads:** local `~/.claude/projects` and `~/.codex/sessions` (replay, read-only);
  hook stdin JSON (live).
- **Persists:** counters, booleans, millisecond offsets, 128-bit
  `HMAC-SHA256(per-install-secret)` change fingerprints and 8-hex failure-signature
  digests. Raw source/diffs/commands/output/prompts are never written; the per-install
  secret lives in `~/.agent-pigeon/secret.key` (0600) and never enters any file the
  product writes or any payload.
- **Transmits:** nothing. No network code exists on any execution path.
- Package content scan: no personal paths, no emails, no keys, no transcripts (verified
  against the built tarball).

## Performance (measured)

- Replay corpus (367 sessions, 1.2 GB, codex+claude): **~11 s** total.
- PostToolBatch delivery path (synchronous, before next model call): **p50 93.1 ms /
  p95 99.0 ms / max 110.1 ms** over 60 runs — Node startup dominated (~90 ms baseline);
  decision logic 1–3 ms. Per-batch, not per-tool.
- PostToolUse observer: async, never on the agent's critical path.

## Remaining limitations

1. Claude live behavioral effect unmeasured (account access) — detection/delivery is
   validated, behavior change is not claimed.
2. RETHINK absent by design (needs confirmed organic stable-outcome windows; current
   signature tooling rebuilt, corpus re-scan pending more data).
3. Jev absent from MVP (value unjudged; interface retained).
4. Failure signatures hash the last 3 normalized content lines — robust against wrapper
   noise, not AST-level; failure identity across differently-phrased but equivalent
   errors is best-effort.
5. Corpus nuance: ~47 verification-only sessions (review/ops usage) legitimately produce
   no attempts; replay numbers are about coding sessions, not all usage.
6. Git remote now exists (github.com/hyukvoid/agent-pigeon) — **not pushed yet**; pushing
   the POC branches is the owner's one-step follow-up.
