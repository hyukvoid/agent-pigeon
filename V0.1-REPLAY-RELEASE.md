## Product surface

Exactly one public command:

```
agent-pigeon replay [--source claude|codex|all] [--json] [--claude-dir] [--codex-dir]
```

plus `--help` / `--version`. Nothing else is routed. `init`/`remove` (live
governor installation) are **gone from the public CLI** — a new user cannot
accidentally enable a withheld experiment.

## What was removed from v0.1

- **Live VERIFY_FIRST governor** (`init`/`remove` commands, observer hook,
  batch delivery hook, watermark policy) — moved verbatim to
  `experimental/` (hooks + sources + its tests). Preserved for research,
  absent from the product surface and from the npm package.
- **RETHINK / HUMAN_REVIEW / Jev** — not implemented, not shipped. The Jev
  provider interface lives only in source, reachable by no public command.
- POC scenario CLIs (`poc:00` demo etc.) — dev scripts, excluded from the
  package.
- Research reports — moved to `docs/research/` (kept; superseded documents
  carry correction banners).

## Verification classification limitations

- Recognizes common build/test/device commands and package-manager scripts
  (`npm run check` etc.). Deliberately excluded: lint/format scripts.
- Does NOT recognize project-specific smoke runs or bespoke scripts
  (`node app.js`) — observed in the dogfood as the residual false-positive
  class for the live policy; in replay it means a stretch may be labeled
  "unverified" even though the agent ran *something*. Hence the
  "recognized" wording everywhere.
- Lint/format scripts deliberately do not count as verification.

## Privacy behavior

- Replay **reads** only `~/.claude/projects/**` and `~/.codex/sessions/**`,
  read-only.
- Replay **writes nothing anywhere** — no secret file, no state, no cache
  (the fingerprint path was removed from the replay pipeline entirely;
  fingerprints now exist only in the experimental live path). Verified by
  the CLI test suite and by clean-directory runs.
- **Transmits:** nothing; the replay path has no network code.
- Output contains aggregate counts and 8-character session identifiers only.

## Parser/security audit

Adversarial inputs tested: malformed JSONL, truncated final records,
1 MB single lines, Unicode, nested fake tool calls, huge patch bodies,
unknown event types. Behavior: parse, skip, or count — never crash, never
execute. Static contract tests assert the parsers and hooks contain no
`eval`, no dynamic import, no child_process, and no transcript execution.
One real robustness regression found during hardening (state-file temp leak
in a test) was fixed.

## Remaining blockers

1. **Live behavior**: the experimental governor needs a dogfood of its own

2. **Linux/macOS validation** before advertising platform support.
3. Kiro/other-agent parsing: absent (documented).
4. Outcome-identity mining (dead-ends, RETHINK) requires a clean-output
   corpus — not available on this machine.

## Strongest reason TO release

The product does one thing, works on real history, is honest about what it
can and cannot see, costs nothing to try (read-only, no config, no network),
and its core finding — verification debt in real agent sessions, including a
window that burned hours of agent work — is demonstrated on real data with
zero false positives after the audit.

## Strongest reason NOT to release

Replay is a mirror, not a fix: it tells you the agent skipped verification,
but v0.1 cannot change agent behavior (the live governor failed its gate, and
the recognition gaps that failed it also bound what replay can see). Anyone
expecting v0.1 to make their agent verify more will have to wait for a later
version — and the improved-classifier evidence (588 recognized runs) shows
the problem is common, not that this tool solves it.
